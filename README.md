# longstorycareer

Résumé and career artifacts for Scott Long — one source of truth, three outputs.

| File | What it is |
|---|---|
| `resume.md` | **The master.** Edit this; everything else is generated from it. |
| `index.html` | Interactive site (GitHub Pages). Self-contained — no framework, no build step, no tracking. |
| `Scott_Long_Resume.docx` | Generated by `build_docx.py`. What recruiters ask for. |
| `Scott_Long_Resume.pdf` | Exported from the `.docx` via Word. |
| `build_docx.py` | `resume.md` → styled `.docx`. |

## The site

`index.html` renders the résumé as an interactive page:

- **Lens filter** — one control row scopes the whole page to *Platform & Infrastructure*,
  *AI & Agentic Systems*, *Backend & Distributed*, or *Leadership*. Each lens shows its item
  count, deep-links as `#lens=ai`, and hides sections that have nothing to say under it.
- **Two charts** — commits authored per year, and the eleven-repository platform build by
  repository. Both carry a hover/keyboard tooltip and a table-view twin, so no value is
  reachable only by pointing at it.
- **Dark mode** — a selected palette, not an inverted one. The toggle beats the OS setting
  both ways and persists.
- **Print** — `Cmd-P` yields a clean document: the filter row and charts drop out, the data
  tables stay.

Everything is one file. Open it locally or serve it — no dependencies either way.

## Rebuilding

```sh
# resume.md -> .docx
uv run --with python-docx python build_docx.py resume.md Scott_Long_Resume.docx

# .docx -> .pdf  (macOS, via Word)
osascript -e 'tell application "Microsoft Word"
  open POSIX file "'"$PWD"'/Scott_Long_Resume.docx"
  save as active document file format format PDF file name "'"$PWD"'/Scott_Long_Resume.pdf"
  close active document saving no
end tell'
```

The site reads no data at runtime — its content model lives inline in `index.html`. When
`resume.md` changes materially, update the `JOBS` / `PROJECTS` / `TILES` constants to match.

## A note on the numbers

Every figure on the résumé and the site is counted from authored git history or verified
against a package registry — not estimated. The commit counts come from `git log --author`
across ~50 repositories; the package release counts come from the npm and PyPI registries.

## A note on what's *not* here

This is a public repository, so employer-internal material is deliberately absent: no project
codenames, no client names, no infrastructure topology, no named colleagues. Systems are
described by what they do rather than by what they're called internally — which reads better to
an outside reader anyway. Contact is by email; direct-send copies carry the rest.
